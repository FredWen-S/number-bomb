# Number Bomb / 猜数字炸弹

2–8 人跨设备在线游戏。无运行时依赖，Node.js 20+ 即可启动。

## 试玩

- 本机：http://localhost:4317
- 本次临时外网地址：https://manchester-dos-customs-boots.trycloudflare.com
- 玩家输入昵称创建房间，把邀请链接或六位房间码发给朋友。全员准备后由房主开始。
- 外网地址依赖本机 Node 与 cloudflared 持续运行，电脑关机、休眠或关闭进程后失效。它不是永久部署。
- 需要新的临时地址时运行 `powershell -ExecutionPolicy Bypass -File start-public.ps1`，它会在需要时启动游戏并打印新的公开地址。

## 游戏规则

1. 服务器随机选择 1–100 的整数作为炸弹。
2. 按玩家加入顺序轮流猜数，每回合 30 秒。
3. 未猜中时缩小可猜范围（含两端），下一位继续。
4. 猜中或超时淘汰；结算展示 2.2 秒，期间禁止输入。剩余玩家用新炸弹进入下一轮。
5. 最后一位玩家获胜，累计本房间胜场。房主可以再来一局。
6. 大厅和游戏结束后可离开，房主离开会把房主权限交给下一位。游戏中断线计时继续，超时淘汰。

## 启动与验证

双击 start.cmd，或在此目录运行 `npm start`。默认端口 4317，也可通过 PORT 指定。
运行 `npm test` 检查游戏规则、完整三轮、权限、超时、隐藏状态、双客户端实时同步和重连。

每个浏览器标签页保存自己的身份；刷新恢复身份。请用另一台设备或独立窗口测试多人。服务器重启会清空房间。房间六小时无状态变更后清理。

## 实现

- game.js：服务器权威状态机 Lobby → Playing → Resolving → Game Over。
- server.js：Node HTTP 服务、SSE 推送（每 10 秒 ping），`/healthz` 健康检查，按 IP 限流（每 10 秒 120 次操作、每 10 分钟 15 个新房间、全服 500 个房间、每房间 24 条推送连接）。
- 客户端只在 SSE 没有收到数据时每秒轮询；Cloudflare 临时隧道会缓冲 SSE，此时自动走轮询。
- 在线状态：大厅里离线超过 60 秒的玩家会被移出，避免卡住开局；游戏结束时房主离线 60 秒会把房主交给在线玩家。房间失效或被移出时页面回到首页并提示。
- public/：中文响应式前端，无打包步骤。
- test/game.test.js：Node 原生测试。

炸弹在揭晓前不发送到客户端，玩家凭随机令牌操作，服务端校验回合、阶段、数字范围及状态版本，防止重复提交。

## 公开托管

当前临时隧道已连通。要获得稳定地址，可将本项目部署到支持持续运行 Node 服务的主机，启动命令为 `npm start`。随附 Dockerfile 和 Render 蓝图 `render.yaml`。

Render 免费部署：把项目推到 GitHub，在 Render 选择 New → Blueprint 并选中仓库，它会按 render.yaml 建一个 Node Web Service（健康检查 `/healthz`），得到固定的 `https://<名字>.onrender.com` 地址。免费实例 15 分钟无访问会休眠，下次打开约需 1 分钟唤醒，休眠或重新部署都会清空房间。

此版本以单进程内存保存房间；不要开启多个独立实例，否则不同玩家可能进入不同状态。长期正式运营需要共享持久化存储和额外的流量保护。不适合仅上传静态文件的托管方式。
